Perceptual tier

off by default — this is the only part of Crush that discards anything
Everything else in Crush is bounded by arithmetic. This tier is not, because it answers a different question: not what are these bytes but what will a person actually see and hear. How Crush decides

1. Identify. Every file is sniffed by structure, not just its extension.
2. Transform. A reversible transform exposes the real content — a Zip-family container is unwrapped, a JPEG is re-coded into JPEG XL's stronger entropy model, PCM audio is run through a linear predictor, a numeric array has its byte planes transposed.
3. Prove it. Every transform is inverted and compared against the original before anything is written. One that does not reproduce the input exactly is discarded and the file falls back to plain compression.
4. Bundle. Files of the same kind are compressed together in one solid stream so redundancy between them is found. Identical files are stored once.
5. Compete. Each bundle is compressed by every codec that suits it — LZMA2 with the right filter, Brotli, Zstandard, PPMd, and the Crush context-mixing engine — and the smallest output wins.

What Crush will not claim. No compressor can shrink every input: there are 2ⁿ files of n bits and only 2ⁿ−1 shorter ones, so any reversible scheme that shrinks some files must enlarge others. Crush never inflates a file — it stores it instead — and it never claims a saving it has not measured.
