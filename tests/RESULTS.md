# crush_crypt adversarial test suite - results

Generated by `test_crypt.py`. Module under test:
`engine/crush_crypt.py` (Argon2id -> XChaCha20-Poly1305 in a STREAM
construction), plus its integration through `crush_engine.compress`,
`read_index`, `extract` and `crush_crypt.EncryptedReader`.

The suite modifies nothing. Two checks set `crush_crypt.HAVE_ARGON2 = False`
**in memory** to exercise the scrypt fallback, and restore it in a `finally`.

## Grading rule for the tamper matrix

A mutated archive passes iff decryption **raises**, or returns plaintext
**byte-identical** to the original (the mutation was a no-op). Returning
*different* plaintext without raising is a silent forgery and is graded
`CRITICAL`. Both decryption paths - `decrypt_file` and `EncryptedReader`
(full read + `verify()`) - are graded independently.

## Verdict

The cryptographic core holds. All 402 mutated archives were rejected with an exception by both decryption paths; not one produced plaintext, wrong or right. Both known-answer suites (HChaCha20 and XChaCha20-Poly1305 from draft-irtf-cfrg-xchacha-03, Argon2id from RFC 9106) reproduce exactly, and the XChaCha layer agrees byte-for-byte with an independent reference over random inputs. The STREAM construction does what its docstring claims: truncation, extension, reordering, duplication, deletion and cross-archive splicing all fail closed, including the cases a plain per-chunk AEAD would accept.


The 2 warning(s) are behaviours worth knowing about rather than defects: a documented sharp edge, a data-loss footgun, a distinguishable error path, and a denial-of-service ceiling set at the format's limit rather than at anything a laptop survives.

## Failures

None.

## Warnings - behaviours worth knowing about

### 3. Tamper resistance - tampered header raises an indistinguishable WrongPassword

version/suite/KDF-parameter corruption raises CryptoError with a field-specific message (version:CryptoError, suite:CryptoError, kdf.t:CryptoError, kdf.m:CryptoError, kdf.p:CryptoError) rather than the WrongPassword the class docstring promises for 'a corrupted or tampered header'. Not exploitable - those bytes are cleartext anyway - but the two failure modes are distinguishable.

### 6. Passphrase strength estimator - the de-leet rule catches leetspeaked words it can see

password_strength('Tr0ub4dor&3') = 72.3 bits ('strong'); zxcvbn scores it near 28. The de-leet rule is correct - it tries the identity substitution per character - but 'troubadour' is not in the 730 strings Crush ships, so the character model stands. Any leetspeaked dictionary word outside the shipped lists scores higher than it deserves. The interface states this limitation and offers Suggest, which is provably 72 bits.
